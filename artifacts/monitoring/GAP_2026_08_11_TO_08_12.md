## Why — the two days failed for different reasons

Log activity windows (`logs/watchdog.log`, `logs/cron.log`, `logs/bellringer.log`):

```
2026-08-11   08:00 → 22:00     host up all day
2026-08-12   08:00 only        no activity after 08:00 ET
2026-08-13   13:14 →           host returns
```

**Day 47 (2026-08-11) — not an outage.** The host was up for the full session and
the evening production run completed normally (`data/snapshots/2026-08-11/` exists;
housekeeping logged 16:50; evening catch-up logged 22:00). The pre-market capture
simply was not taken. This artifact has no cron entry and no generator script — it
is produced by an interactive session — so a morning with no session produces no
snapshot, independent of host health.

**Day 48 (2026-08-12) — outage.** Host activity ceased after 08:00 ET, before the
~09:30 pre-market window, and did not resume until 2026-08-13 13:14. Both the
pre-market capture and the daily production run were lost. Production was
backfilled on 2026-08-13 by `cron_daily_production.sh --catch-up`
(`data/snapshots/2026-08-12/rankings.csv`, 300 lines). **The pre-market capture was
not backfilled and cannot be.**

A stale `.git/index.lock` dated `2026-08-12 17:57:57` was found and cleared on
2026-08-14. WSL logged nothing at that time; the repo lives on `/mnt/c`, so this was
most likely a Windows-side git process. Noted for completeness — it is not the cause
of either gap.

## Why these cannot be reconstructed

There is no generator. Searches across `tools/`, `scripts/`, `agents/`, the full
repo, the crontab, and `~/.claude/skills/` find nothing that writes
`artifacts/monitoring/daily_*.json`. The only skill referencing these files
(`biotech-performance-report`) reads them.

Each snapshot is an observational record of a specific live moment, not derived
output. Day 46 for reference:

```
timestamp: 2026-08-10T09:37:00.000000Z
phase:     "Day 46 — PRE-MARKET / OPEN snapshot (Aug 10 09:35-09:37 ET) …
            DATA NOTE: Yahoo Finance returned stale/incorrect data for
            multiple tickers this session — all prices sourced from
            Finviz (timestamped 09:35-09:37 ET)."
positions: 15 live positions
account:   live balances
```

Reproducing Days 47–48 would require inventing prices at 09:35–09:37 ET on dates
now past, account and position state at those instants, and a session narrative
written with hindsight. Daily OHLC cannot reproduce a 09:37 tick, and the account
has since moved. Producing such files would place fabricated point-in-time evidence
into a chain that feeds the governance gates, in files whose names and schema are
indistinguishable from genuine captures. A retrospective reconstruction was offered
and declined in favour of this record.

## Downstream handling

- Any series, count, or chart reading `artifacts/monitoring/daily_*.json` **must
  treat Days 47–48 as absent, not zero.** Interpolating or zero-filling them
  misstates the record.
- The `monitoring_day` counter is unaffected: Day 49 = `2026-08-13` is correct, and
  Day 50 = the next captured session. Day numbers track calendar sessions, not
  captured files, so the sequence does not need renumbering.
- Do not treat the Day 46 → Day 49 interval as three days of continuous
  observation.

## Preventing recurrence

Day 47 is the actionable one: a healthy host still produced no capture, because
nothing schedules this artifact. If continuous coverage is wanted, the capture
needs a scheduled trigger rather than reliance on a morning session being held.
Day 48 would not have been saved by scheduling — the host was down through the
window — but would at least have been flagged as a missed run rather than silently
absent.

No such trigger is being added by this record; it documents the gap only.
